# Troubleshooting

**Live queue waiting / no iMessages:** install phone app 2.3 (build 6), update the server source, and check that the Messages user is logged in and its reader LaunchAgent is running. Grant Full Disk Access to the bundled Node executable as described in DEPLOYMENT.md, then rerun `node scripts/phone-wall/install-messages-agent.mjs` as that user. Wait for the reader's connected status before sending a new incoming message from another account/number. First connection skips existing history; outgoing messages and reactions are intentionally ignored. The backend `_phonewall` account cannot read a user's Messages folder and is not used for ingestion. The reader-install command is needed only for one-time setup or permission recovery.

**Queued messages but a row does not start:** all configured phones in that row must be online, updated and running the live artwork. Other complete rows continue. Inspect the phone error log below the matrix for preparation errors. On a live-artwork cache or storage error, the controller asks that phone to clear its cache once and retries with increasing delays, without deleting the message queue. Phone app 2.4.3 is required for this command to clear both downloaded media and prepared artwork bundles; older apps clear downloaded media only. Night mode, pairing or a selected-phone blackout can hold a row. Runs interrupted by outages are retried, so partial visible repeats are possible. A database ROWID reset or attributed-body decoding error is shown rather than silently skipping data; preserve the DB/cursor and contact the installer.

**Controller fails to start:** verify `PHONE_WALL_ADMIN_TOKEN` is 32+ characters, Node is at least 22.13, and `npm ci --prefix server/phone-wall` completed. Check persistent directory permissions, free disk and port conflicts. Meteor and MongoDB are not needed for the standalone service.

**Mac restarted but service absent:** the Node controller is a system LaunchDaemon. Check `launchctl print system/org.museum.phonewall`, `/health` and `/Library/Logs/PhoneWall/server.log`. The iMessage reader separately starts at Messages-user login.

**Discovery fails:** confirm dedicated Wi-Fi, local-network permission, multicast/mDNS availability and only the intended installation on that LAN. The service advertises `_phonewall._tcp`. Configure the stable fallback URL when multicast is blocked. Router client isolation may block both Bonjour and ordinary traffic. Discovery does not require internet.

**Connections repeatedly drop after an update:** check the connected phone count and the dashboard's Last connection issue for affected phones. Each installed build clears saved connection metadata on first start; if the problem persists, use Advanced > Installation Reset for a full controller data reset and re-pair. That action also sends a media cache clear command to phones connected at the time. It erases queued live messages and wall settings, so export anything needed before using it.

**One phone connects but others wait:** enable Local Network permission for PhoneWall on each phone and confirm all phones use the installation Wi-Fi. App 2.1 bounds the connection handshake to ten seconds, retries Bonjour resolution, and lets discovery replace a stale in-flight fallback. The setup label shows the hostname actually being contacted; after welcome the address field shows the resolved endpoint. Pairing chips explicitly label ONLINE/OFFLINE: saved unpaired records are not evidence of live connections. Reinstall the updated IPA over the old one without deleting the app to preserve identity. If access is denied or Wi-Fi isolates clients, code retries cannot fix that network policy.

**Mac changes its name to sms-ingestor-2.local:** legacy controller 2.0.0 incorrectly published host address records independently of macOS. The current Node daemon uses system Bonjour. The corrected version registers only a service using system Bonjour, retains data and does not require an IPA update. The suffix may remain until you edit the local hostname in System Settings > General > Sharing. Automatic discovery works with the suffix; do not force the original name if another real machine uses it.

**401 / pairing lost:** operator key and device secret serve different roles. Import full credential hashes before switching an existing wall. A deleted/reinstalled app obtains a new identity and needs pairing. Never copy a phone's identity file to another phone. An unreadable identity file fails closed; recover it with installer assistance.

**Phone becomes dark:** runtime 2.0 should keep the last good artwork during connection loss. Check night/blackout mode, whether a good release has ever activated, identity/storage availability and per-deployment errors. Restore server/Wi-Fi and let backoff retry; reconnect requests a complete snapshot. Do not reinstall the app to fix a transient outage, since reinstalling removes cached identity/artwork.

**Stale edit rejected:** reload current JSON or merge your intended changes; configuration edits require expectedRevision. Rollback creates a new revision. A preview temporarily overrides base artwork for its target and expires automatically. Resume clears persistent targeted overrides; global mode controls clear all temporary previews.

**Scene does not change on one group:** check selected target scope, IDs/groups in configuration and pending pairing. Native renderer kinds are fixed in the IPA; use supported scene parameters or the experimental web renderer for rapid visual changes. New native APIs/codecs require a client update.

**Media preparation fails:** inspect the target's deployment error: missing/invalid asset, checksum, renderer timeout or cache budget. The working release stays visible. Current and previous assets are pinned; Clear Cache removes unused assets rather than destroying last-good content. Prefer modest resolutions and compatible muted H.264 MP4 on A9 devices. Total declared assets per release are limited to 200 MiB; current + previous + candidate must fit the 512 MiB cache budget. Stage groups to preload over constrained Wi-Fi.

**Experimental visual fails:** inspect the release's script/version and PixiJS API use. Declare all resources, avoid CDN/fetch dependencies, and use PhoneWall.onFrame for timeline rendering. For async setup use manualReady + PhoneWall.ready(). WebKit errors/termination/missed heartbeats recreate the cached view up to three times per minute; exhausted recovery reports failure and falls back. A failed deployment is quarantined to avoid repeated crashes; deploy a corrected release or explicitly deploy again. Native runtime fixes still require an IPA.

**Ticker seams:** verify geometry including bezel gaps, mounted orientation, clock samples and Wi-Fi latency. Use the shared-time bar and measure actual adjacent-screen skew. Frame-perfect sync is not guaranteed.

**IPA does not install / app terminated:** verify registered UDID, signing identity, profile/certificate expiry and bundle ID. Use Configurator if debugger deployment is unsupported. Follow the tested Single App Mode USB recovery workflow; an ordinary app cannot turn on or reboot an iPhone.

## Repeated Disconnects / Misleading Charging

Push the Mac source to `phone-wall-runtime-2`; run the Mac pull-and-restart command to deploy it. Native recovery changes still require an in-place phone app update. Idle phone output is now black; Identify has static labels only, with no grid/moving bar. The server keeps authenticated sockets open for stale artwork/optional-message errors, while malformed/authentication/rate-limit errors remain fatal. Click a matrix phone and inspect **Last connection issue** / **Last disconnect** after updating; these are historical diagnostic records, not necessarily a current outage. The controller's sanitized log is `/Library/Logs/PhoneWall/server.log`.

`device-identity-conflict` means two active boot sessions presented the same saved device ID/token, or a restarted app's old socket has not yet expired. The existing connection is no longer evicted. Allow up to the 45-second liveness window after a restart. If persistent with two physical phones, investigate cloned app data/identity and re-enroll the affected phone deliberately; do not erase all devices or change Wi-Fi as a first step. `unsupported-message` / `unknown-deployment` previously caused reconnect loops and now return nonfatal errors. `rate-limit` and malformed frames still require investigation. Charging labels reflect actual health-report timestamps; reconnecting alone cannot make old data fresh. Unknown battery state is not labeled Unplugged. The museum's specific cause requires its device/log diagnostics; a reachable health endpoint alone does not prove a stable socket.
