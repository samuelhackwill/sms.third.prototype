# Staff quick guide

Use this guide after an installer has paired and tested all screens.

**Roland Barthes Mode:** In Control, press Start Roland Barthes Mode after pairing phones. The controller loops through the bundled sentence archive in order, fills available rows automatically, and assigns a different speed from 1,000–6,000 logical pixels per second to each sentence. Text is green on black. Stop Roland Barthes Mode to end playback. Starting Live iMessages or another artwork pauses it; incoming iMessages remain queued for Live iMessages.

## Connection recovery and installation reset

Updating the controller restarts its WebSocket listener and Bonjour registration. On the first start of each installed build, it clears saved connection diagnostics and heartbeat readings, then phones reconnect with fresh telemetry. Pairings, wall settings, media and the live-message queue remain in place. Check the connected phone count after the pull; a lower count calls for checking the dashboard and service log.

For a full reset, open **Advanced > Installation Reset > Reset Installation Data**. Confirm to erase the controller's pairings, wall settings, queue and downloaded media. The controller sends `clearCache` to currently connected phones, restarts, and shows a new installation in the dashboard. Pair the phones again. Offline phones cannot receive the cache command; their saved controller URL and device identity remain on the phone. The controller log remains available for diagnosis.

To assign positions (app 2.1+): open **Pair / Position** and press **Start Pairing Mode**. Connected phones turn red. Tap each phone once, starting at the top left, moving left-to-right across each row, then down. Wait for green confirmation before tapping the next phone. Press **Stop Pairing** on the Mac whenever finished, even with fewer than 30 phones. Assignments are saved immediately; a full wall stops automatically. Starting another session begins again at slot 0 and replaces positions as you tap, without erasing untouched slots. Pairing expires after ten minutes for safety.

The dashboard opens on **Control**: Pair / Position first, **Send Test Text** second. Stop pairing, then press Send Test Text for red serif letters on black, once across each occupied row, right-to-left, with 750 ms between row starts. The actual text/emoji glyph bounds are measured and fitted to 97% of the shortest phone's height in that row, avoiding clipping and preserving a common row baseline. Emoji retain their normal system colors. This style uses the existing cached web-artwork renderer so it can change through GitHub without another IPA; WebKit paces its frames, independently of the native display-link target. It resumes exhibition mode and reports preparation/failure; offline paired phones are skipped and counted rather than blocking the test. The previous artwork remains in Advanced releases for reuse/rollback. All previous tools, including Night Mode, the virtual matrix, manual slot fields and scene editor, are preserved in **Advanced**.

**The Matrix**, the compact sticky column beside Control and Advanced, shows the controller's expected output per assigned phone, with state refreshed every three seconds. Test text draws directly in the matrix canvas using the phone renderer’s text-fitting calculations, layout and start time; selection and the web-preview checkbox are unnecessary. Tiles show battery percentage, plugged/unplugged status and thermal category (Heat OK, Warm, Hot or Critical). Additional badges flag low battery, app errors, background state, stale/offline readings or display callbacks below 75% of the reported target. Offline power readings are marked Last report. Click a tile to open persistent diagnostics, including whether the text test is waiting, displaying or finished. Plugged includes both charging and fully charged phones. Thermal categories are not temperature measurements, and callback rate is not a CPU measurement. Clicking only inspects a phone; use Select for Advanced actions in its details, then Advanced → Target: Selected phones, to target commands. On smaller screens the matrix stacks below the controls. Opening the dashboard joins the current point in the animation; it does not replay the one-pass text. Pairing colors, Identify, Night Mode and Blackout are also represented. Empty slots have no assigned output. Each card separates expected artwork from the phone's reported scene/status; an offline phone may differ from the controller preview. Other web artwork requires selecting phones and enabling web previews (up to four); image/video previews remain placeholders. Local draft previews are explicitly labeled; **Show Live Wall** returns to controller state.

Use the **Text speed** slider (20–1000 logical pixels/second) before sending a test. Try 80–120 for slower movement; the original speed was 240. It changes the next test, not the text already moving. The last sent speed is saved on the controller and restored when reopening the dashboard. The **Test message** field accepts text and emoji, including skin tones, joined sequences and flags; message and speed are saved together. No phone update is required for these controls. Only emoji provided by the phone's installed iOS can be guaranteed; newer unsupported glyphs may show missing-character boxes.

Native app **2.2 (build 5)** requests **60 frames/second**; older 2.1 apps requested 30. Install this IPA once for the smoother native renderer; GitHub server updates cannot change native code. **Advanced** phone cards show sampled display-callback rate and target after a heartbeat. This is a useful slowdown diagnostic, not proof every frame reached the screen. Actual sustained performance, thermals and battery behavior must be checked on the iPhone 6s. Speed and frame rate are independent. The browser's 30-screen preview remains approximate and capped around 30 fps; video and experimental WebView frame rates depend on their own playback/render loop.

Push a server update to `phone-wall-runtime-2`; run the Mac pull-and-restart command to fetch and restart. Normal playback remains local once the update has downloaded. Artwork-only changes do not require an IPA update.

## Independent Kissing Wall

Install phone app **2.4.3 (build 10)** once, then use **Control > Kissing Wall > Start Kissing Wall**. Each phone plays its own random clip, with sound enabled. Set speaker volume using each phone's volume buttons; a clip with no audio track is naturally silent. The Mac initially downloads clips from the original kissing API and shares verified files locally. The pool grows gradually, so the first clip may repeat until more arrive. Internet is required to obtain new clips, not to replay cached ones.

Optional **Play only the kiss** uses the API kiss timestamps and the before/after padding. Fade and trim settings apply to the next clip without an IPA update. Night Mode, Blackout and pairing pause video/audio; Resume continues it. Stop Kissing Wall returns to the previous artwork. Starting test text, live messages or another published artwork exits kissing mode. The phone error log below the matrix shows reported video errors. Enable Phone Debug Display to see app version, connection state and the latest error code on phones running app 2.4.3 or newer.

## Full Frame Clips

Use **Control > Full Frame Clips > Start** on the desktop dashboard to play one cached kissing clip across the entire phone matrix. Each connected phone displays its portion of the same video. With phone app 2.4.7, sound plays on every phone at the dashboard volume and clips do not repeat while the next one prepares. The controller schedules the next clip at the current clip's end; if preparation is late, the finished frame waits. **Stop** returns to Roland Barthes Mode. Incoming SMS continue to be archived and queued while this mode is active, then resume display when it stops. Clip metadata is read locally with `ffprobe` on the Mac mini.

## Live Incoming Messages

After the one-time [Messages setup](DEPLOYMENT.md#live-imessages-one-time-setup-on-sms-ingestor) and phone app 2.3 installation, open the browser dashboard. Polling and playback start automatically. Wait for the reader's connected status before sending the first new incoming message. The first database connection skips old history. Each message enters one FIFO; whichever row has at least one ready phone takes the oldest waiting message. Its participating phones start together after preparing the text; the row becomes free after those phones confirm the text has left.

The reader continues polling through artwork changes. Night mode, pairing, Kissing Wall and Barthes mode temporarily hold incoming-message playback while retaining messages in the queue. Playback resumes when the temporary mode ends. Test Text and other artwork actions do not turn off incoming messages. A row can play with any ready phones, even if only one of its five phones is available. Interrupted/unfinished runs return to the queue; a partially seen message may replay after a network/server interruption rather than being silently lost. Duplicate database deliveries do not create duplicate queue entries.

If the reader needs Full Disk Access, follow the on-screen permission instructions and reopen the Mac dashboard. Messages ingestion requires the Mac's Messages user to remain logged in. Do not grant this access on a personal machine/account containing conversations you would not want broadcast. Original Messages data is never changed or erased by Phone Wall.

Artistic editing and staged release instructions are in [RUNTIME.md](RUNTIME.md). Use one phone, then a selected group, then promote the same immutable release to the entire matrix. Do not treat a release as successful until its target phones report displayed; a preparation error leaves the previous artwork in place.

1. Switch on the dedicated router and screen chargers, reconnect Mac mini power, then press the Mac mini's power button. The controller starts before anyone logs in. Restored power alone will not reliably start this M1 Mac after a deliberate shutdown.
2. Open `http://127.0.0.1:3100/admin/phone-wall` in a browser on the Mac mini (or use the configured port). Enter the operator key once for that tab session. Check the device count and status labels.
3. For the approved exhibition artwork, open **Advanced** and press **Start Exhibition**. Check all screens. If a scene needs selecting, choose the approved scene before starting.
4. Before moving or unplugging the installation, use **Shut down installation** on the museum remote and confirm. It puts connected phones in Night mode, then shuts down the Mac mini. Wait until the Mac mini's power light is off before unplugging it. After reconnecting power, press the Mac mini's power button; the controller starts without a macOS login and restores Exhibition mode.
5. Set Target to **Entire matrix** and use **Blackout** for an immediate black display. Use **Start Exhibition** to resume. Manual mode controls disable an enabled daily schedule; the installer must save the schedule again to reactivate it.
6. For a missing screen, find its Offline card. Click a neighboring paired screen, choose **Select for Advanced actions** in its details (repeat for other phones), set Target to **Selected phones**, then press **Identify**. The test pattern lasts 15 seconds. Check the missing phone's cable, charger and Wi-Fi. Ask the installer for USB recovery if it does not return. Return Target to **Entire matrix** afterward.

After an outage, restore router, chargers and Mac power and wait for reconnect. The Node controller starts at boot, before login; logging in to the Messages account is needed for iMessage ingestion. A fully powered-off iPhone cannot be switched on remotely by this app; use its physical power button if needed. Single App Mode reboot/autolaunch must have been verified for the deployed build.

Keep ventilation clear and cables secured. Remove any phone with a swollen battery, abnormal heat or unstable charging from service. Do not use personal accounts or store personal information on installation phones. The dedicated router travels with the wall when moving rooms.
